# 📧 Email-уведомления при смене пароля

## Обзор

При смене пароля в профиле пользователя автоматически отправляется email-уведомление на почту. Это критически важная функция безопасности, которая позволяет пользователю узнать о несанкционированном доступе к аккаунту.

---

## 🔒 Зачем это нужно?

### Безопасность
Если кто-то получил доступ к аккаунту и изменил пароль, владелец немедленно узнает об этом через email.

### Прозрачность
Пользователь контролирует все изменения в своем аккаунте и получает подтверждение каждого действия.

### Правовая защита
Наличие уведомлений доказывает, что система предупредила пользователя о критических изменениях.

---

## 📝 Что включено в письмо?

### Основная информация:
- ✅ **Дата и время** смены пароля (в UTC)
- ✅ **IP-адрес** с которого была выполнена смена
- ✅ **Имя пользователя** (ФИО или email)

### Элементы безопасности:
- 🚨 **Кнопка "Восстановить доступ"** - прямая ссылка на главную страницу для восстановления пароля
- ⚠️ **Предупреждение** - что делать, если это был не пользователь
- ℹ️ **Успокаивающее сообщение** - если пользователь сам менял пароль

### Процесс отправки:

1. Пользователь меняет пароль в профиле
2. Backend валидирует старый пароль
3. Backend устанавливает новый пароль
4. Backend сохраняет изменения в БД
5. Backend получает IP-адрес из request
6. Backend отправляет email-уведомление
7. Если email не отправился - пароль все равно изменен (fail-safe)

## 🔧 Настройка Email

### Для разработки (Console Backend):

Уже настроено в `backend/.env`:
```env
EMAIL_BACKEND=django.core.mail.backends.console.EmailBackend
```

Письма будут выводиться в консоль backend.

### Для продакшена (SMTP):

Обновите `backend/.env`:
```env
EMAIL_BACKEND=django.core.mail.backends.smtp.EmailBackend
EMAIL_HOST=smtp.gmail.com
EMAIL_PORT=587
EMAIL_USE_TLS=True
EMAIL_HOST_USER=your-email@gmail.com
EMAIL_HOST_PASSWORD=your-app-password
DEFAULT_FROM_EMAIL=noreply@sm-market.com
FRONTEND_URL=https://your-domain.com
```

Подробнее см. [EMAIL_SETUP_GUIDE.md](EMAIL_SETUP_GUIDE.md)

## 🛡️ Безопасность

### Что ВКЛЮЧЕНО в письмо:
- ✅ Дата и время смены
- ✅ IP-адрес
- ✅ Имя пользователя
- ✅ Ссылка на восстановление доступа

### Что НЕ ВКЛЮЧЕНО (никогда!):
- ❌ Новый пароль
- ❌ Старый пароль
- ❌ JWT токены
- ❌ Любые секретные данные

### Fail-Safe механизм:
Если отправка email не удалась (проблемы с SMTP, сетью и т.д.), пароль все равно будет изменен. Это важно, чтобы пользователь не остался заблокированным из-за проблем с почтой.

Ошибка отправки логируется в консоль:
```
Error sending password change email: [error details]
```

## 🔍 Получение IP-адреса

Функция `get_client_ip(request)` корректно обрабатывает:

1. **Прямое подключение:**
   ```python
   ip = request.META.get('REMOTE_ADDR')
   ```

2. **Через прокси/балансировщик:**
   ```python
   ip = request.META.get('HTTP_X_FORWARDED_FOR').split(',')[0]
   ```

3. **Неизвестный IP:**
   ```python
   ip = 'Unknown'
   ```

## ❓ FAQ

### Q: Что если email не отправился?
**A:** Пароль все равно будет изменен. Ошибка логируется, но не блокирует процесс.

### Q: Можно ли отключить уведомления?
**A:** Нет, это критическая функция безопасности. Уведомления обязательны.

### Q: Куда ведет кнопка "Восстановить доступ"?
**A:** На главную страницу сайта, где есть форма входа и кнопка "Забыли пароль?".

### Q: Почему в письме указан UTC, а не местное время?
**A:** UTC - универсальное время. Пользователь может конвертировать его в свой часовой пояс.

### Q: Что если пользователь не получил письмо?
**A:** Проверьте:
1. Папку "Спам"
2. Правильность email в профиле
3. Настройки SMTP в `.env`
4. Логи backend на наличие ошибок
