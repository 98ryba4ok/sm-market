# Складской учёт SM Market

## Открыть и запустить

Адрес: **http://127.0.0.1:5173/warehouse**.

Двойной щелчок по **Запустить склад.command** запускает сайт и API. Держите окно запуска открытым; Ctrl+C останавливает серверы. Если адрес уже открывается, повторно запускать не нужно.

Демонстрационный сотрудник только для локальной базы:

- Email: `warehouse@local.test`
- Пароль: `Warehouse-demo-2026!`

В меню авторизованного сотрудника магазина есть пункт **Складской учёт**. Покупателям склад недоступен; API проверяет права независимо от интерфейса.

## Как пользоваться

1. Добавьте товар: название, уникальный в справочнике артикул, категория, штук в коробке, цена продажи за штуку. Начальный остаток равен нулю.
2. Нажмите **Приход**, выберите товар, укажите коробки и отдельные штуки, закупочную цену за штуку, дату и время, основание.
3. Нажмите **Расход**, заполните количество, цену за штуку и основание. Расход больше доступного остатка не проводится.
4. В **Остатках** показаны штуки, коробки и оставшиеся отдельные штуки. Поле даты показывает остаток на конец выбранного дня по Москве; верхние карточки всегда показывают текущие значения.
5. В **Журнале операций** доступны поиск по товару/артикулу/номеру заказа, вид операции, период с даты по дату включительно. Для месяца выберите его первый и последний день.
6. Кнопка со стрелкой возврата у ручной записи создаёт обратную операцию текущим временем. Укажите причину. История не удаляется. После исправления при необходимости внесите правильную запись.
7. Нажмите на размер упаковки в таблице, чтобы изменить штук в коробке. Общее число штук не меняется; старые записи журнала сохраняют прежнюю упаковку.

Пример: приход 5 коробок по 12 штук, расход 17 штук → **43 штуки = 3 коробки и 7 штук**.

Цены прихода и расхода сохраняются в соответствующих операциях. Сумма операции — количество штук × цена за штуку. Это количественный складской учёт; расчёт прибыли, НДС и себестоимости по FIFO не добавлялся.

## Заказы сайта

Списание выполняется при оформлении заказа, как и в исходной версии сайта, теперь с записью в журнале. Повторная оплата не списывает товар снова. Отмена допустимого к отмене заказа возвращает товар один раз. Отменённый заказ нельзя открыть повторно; создайте новый.

И ручные операции, и заказы используют один сервис изменения остатка с транзакцией и блокировкой товара. Оформление одной корзины также блокируется. Остаток повторно проверяется непосредственно при записи. Правка остатков напрямую и редактирование/удаление строк оформленного заказа через админку отключены, чтобы не обходить журнал.

## Данные

Локальная база: `backend/local.sqlite3`. Данные сохраняются после перезапуска сайта и браузера. В базе находятся явно демонстрационные товары и операции, созданные для проверки; она не является копией рабочего магазина.

Локальная конфигурация `config.settings_local` использует SQLite и выключает реальные платежи, отправку почты и Telegram. Она запускается только на 127.0.0.1. Запросы фронтенда направлены в локальный backend на порту 8000.

При подключении учёта к существующей базе миграция `inventory/0002` заносит текущие остатки как начальные. Более раннюю историю восстановить из одного числа нельзя: система не выдаёт неизвестный остаток за ноль. Новые операции могут иметь прошлую дату, если она не раньше начальной записи товара и не создаёт отрицательный остаток в последующей истории.

Демо-команда `seed_warehouse_demo` запускается только с локальной SQLite-конфигурацией. При повторном запуске сохраняет существующие данные, а не очищает базу.

Для резервной копии остановите сервер и скопируйте `backend/local.sqlite3` в безопасное место. База, окружение и зависимости исключены из Git.

## Установка на другом компьютере

Нужны Python 3.12+ и Node.js 22 LTS. Из корня проекта:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.txt
cd frontend
npm ci
cd ..
.venv/bin/python backend/manage.py migrate --settings=config.settings_local
.venv/bin/python backend/manage.py seed_warehouse_demo --settings=config.settings_local
```

API:

```sh
.venv/bin/python backend/manage.py runserver 127.0.0.1:8000 --settings=config.settings_local
```

Сайт в другом окне терминала:

```sh
cd frontend
LOCAL_BACKEND_URL=http://127.0.0.1:8000 npm run dev -- --host 127.0.0.1
```

## Проверки

```sh
.venv/bin/python backend/manage.py test apps.inventory --settings=config.settings_local
.venv/bin/python backend/manage.py makemigrations --check --dry-run --settings=config.settings_local
cd frontend
npm run build
```

Проверяются пересчёт коробок, точность цен, запрет перерасхода, повторные запросы, права сотрудника, исторический остаток, московские границы дат, исправления, смена упаковки, оформление/оплата/отмена заказа, повторная отмена, откат заказа при нехватке товара. Тесты выполняются на отдельной временной SQLite-базе и не меняют демонстрационные данные. Конкурентная нагрузка на PostgreSQL в локальной проверке не воспроизводилась.

Код склада: `backend/apps/inventory/` и `frontend/src/pages/WarehousePage/`.
Изменения локальные, без публикации и отправки в GitHub.
